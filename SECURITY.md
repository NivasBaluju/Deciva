# Security Policy

## Supported Versions

| Version | Supported          |
| :---    | :---:              |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

Deciva is built with a zero-trust, institutional security posture. We take all vulnerability reports seriously.

If you believe you have found a security vulnerability in Deciva, please do **not** report it through a public GitHub issue.

Instead, please send a detailed disclosure report to:
**`security@deciva.com`**

### What to Include in Your Report
- Type of issue (e.g. CSRF, SQL Injection, IDOR, Privilege Escalation)
- Affected endpoints or files
- Clear, step-by-step reproduction instructions or proof-of-concept
- Any relevant logs or request/response headers
- Impact assessment

### Our Commitment
- We will acknowledge receipt of your vulnerability report within 24 hours.
- We will provide a timeline for investigation and remediation.
- We will coordinate public disclosure once the patch has been verified and deployed.
